# U6003: Call depth or memory limit exceeded

`una run`, `una test` and native executables abort when the calls in progress exceed the maximum call depth: 10,000 by default, or the value of `--max-depth` (`spec/11 §7`). The diagnostic points at the call that goes one level too deep. Calls of functions, predicates, lambdas, policies and handler operations all count. Most often a recursion never reaches its base case; a recursion that is only deep can run with a higher `--max-depth`, up to what a stack of 1 GiB holds.

They also abort when a call finds the run holding more memory than its budget: 4096 MiB by default, or the value of `--max-memory` in MiB (ADR 0061). The message then reads `this call exceeds the memory limit of N MiB`. A program that holds every intermediate value, such as a recursion that keeps each step's text, can hold less, or run with a higher `--max-memory`.

An `Int` of any size is written as text, in time close to that of one multiplication of its size (`spec/11 §7`, #1223). Before converting a large one, a write reserves the bytes of its text and of the conversion, about 96 per 64 bits of the integer, against the memory budget: when they do not fit, the run aborts with the memory message above at the interpolation, the call of `to_text` or `to_json`, or the operation whose event shows the value. Keep such an integer unwritten, write a part of it, or run with a higher `--max-memory`. Until #1223, a run aborted with U6003 when it wrote an `Int` of more than 4300 digits, whatever its budget.

A native executable whose program has a task construct or a `for ever` also stops with U6003 before `main`, with no position and the message `the threads and stacks of this run's tasks could not be made`, when the system refuses its threads or the 64 task stacks it reserves before `main` (`spec/27 §1`). Each stack holds 16 MiB plus `--max-depth` times the program's frame bound, the largest frame its compiled code takes per call, and never more than the about 328 MiB that `--max-depth` alone gives at the default 10,000 (`spec/27 §4`). With a frame bound of 128 bytes the run reserves about 1.1 GiB of address space, of which it uses only what its tasks touch. A Linux system with strict overcommit (`vm.overcommit_memory=2`) can refuse that reservation; a lower `--max-depth` shrinks it.

A run granted `Http` also starts, before `main`, the threads of its requests: `--io-threads` helpers, as many connect threads, and `max(2, --io-threads / 4)` lookup threads (`spec/24 §4`), besides `--workers` and `--file-threads`. A large `--io-threads` can pass the system's limit on a process's threads: at 4096, about 9,200 threads with the defaults, beyond macOS's usual limit (`kern.num_taskthreads`, often 8192) and many containers' limit on processes and threads. The run then stops with U6003 before `main`, with no position and the message `the lookup and connect threads of this run's requests could not be made`, or `the threads and stacks of this run's tasks could not be made` when the helpers are refused. A smaller `--io-threads` runs.

Running out of depth or memory is outside the noninterference model (`spec/07 §1`).

## Failing example

```una
module demo

countdown(n: Int) -> Int = if n == 0 then 0 else countdown(n - 1)

pub main() -> Unit
=
  let steps = countdown(-1)
  unit
```

## Fixed example

```una
module demo

countdown(n: Int) -> Int = if n <= 0 then 0 else countdown(n - 1)

pub main() -> Unit
=
  let steps = countdown(-1)
  unit
```
